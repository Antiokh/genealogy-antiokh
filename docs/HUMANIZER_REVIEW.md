# Русская редколлегия — Humanizer

В генеалогии используется [`Antiokh/humanizer_russian`](https://github.com/Antiokh/humanizer_russian) для **необязательной стилистической проверки** изменённых русскоязычных Markdown/MDX-страниц в `src/content/docs/`.

Режим: `editorial_board`, стиль `neutral`, восемь редакторских библиотек. Версия закреплена на `81af17bcb18ae9364a9f94f4e2f849a68d3b1eee` в обоих workflow.

## Область проверки

- Передаётся **полный читательский текст** изменённой страницы. Из YAML frontmatter исключаются все поля, в том числе `title`, `description`, имена родственников, даты, связи и структурированные данные. Эти поля редактируются только вручную.
- Техническая разметка Markdown/MDX, код и служебные выражения исключаются. В адаптере `.github/scripts/humanizer_pr_review.py` используется логика подготовки видимого текста из RSLive.
- Анализируются полная базовая и полная новая версии каждой статьи. PR получает **только новые замечания**, а не существующий редакционный долг.
- Редколлегия всегда показывает восемь редакторских библиотек; при отсутствии новых замечаний сообщает об этом. Отзыв публикуется как комментарий PR и как GitHub Actions Summary.
- Никакой автоматической замены текста, проверки «на ИИ» или обязательного блокирования merge. Замечания по стилю не отменяют прямые свидетельства в автобиографии и не служат доказательством фактической ошибки.

## Безопасность

Workflow `.github/workflows/humanizer-russian-review.yml` с правом комментирования запускает адаптер **только из базовой ревизии PR**; предложенная ветка содержит лишь проверяемые данные. Для внешних fork PR комментарий не публикуется. Ревью одной и той же PR-ветки выполняется последовательно, более старый запуск отменяется. Служебный маркер `<!-- genealogy-humanizer-review -->` позволяет обновлять прежний комментарий.

`.github/workflows/humanizer-input-contract.yml` имеет только права чтения. Он проверяет синтаксис адаптера, SHA движка, API редколлегии и исключение служебного YAML. Первый PR, добавляющий workflow, проходит контракт, но полноценный PR-review начинает работать **после слияния интеграции в main**.

## Ручная редактура

Humanizer — инструмент поиска возможных языковых проблем, не семантический фактчекер. В частности, он не обязан заметить ошибочную формулировку «Жулебино тогда ещё находилось за МКАД». Проверяйте смысл, топонимы, родственные связи, временную последовательность и сохранность прямой речи отдельно.

При сомнениях между стилистическим советом и буквальным смыслом семейного свидетельства приоритет у исходного свидетельства. Основное правило проекта о первичных автобиографических источниках остаётся обязательным.
