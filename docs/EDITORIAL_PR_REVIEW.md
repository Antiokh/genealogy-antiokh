# Редакторская проверка PR с биографиями

Проверка читательского текста запускается на обновлениях PR и на изменениях `main` для открытых PR того же репозитория. Она **не меняет** биографии, генеалогические отношения, даты, источники или frontmatter.

- Область: только `src/content/docs/people/**/*.{md,mdx}`. Файлы графа, импорта, источников и медиа не передаются на стилистическую проверку.
- Инструмент: зафиксированный по полному SHA `Antiokh/humanizer_russian`, режим `neutral`. Дополнительно проверяются явные редакционные метафразы («в этой карточке», «во frontmatter» и т. п.) — отдельная проверка жанра биографии.
- Отчёт: один Markdown-комментарий с раскрывающимися редакторскими разделами и скрытыми техническими сведениями. Показываются только новые находки относительно base. Все советы необязательны.
- Inline: до 8 комментариев на **добавленных** строках diff, с объединением замечаний на одной строке и дедупликацией по идентификаторам. Если исходный фрагмент нельзя сопоставить однозначно, он остаётся в сводке.
- Безопасность: исполняемый адаптер читается только из доверенной базовой ревизии. PR из форка и Dependabot не получают привилегированной публикации. Владелец существующего комментария должен быть `github-actions[bot]`; текущие head/base SHA перепроверяются до записи. На ошибках старый отчёт заменяется уведомлением о недоступности.
- Файлы: `.github/workflows/editorial-review.yml`, `editorial-base-refresh.yml`, `editorial-contract.yml`, скрипт `editorial_pr_review.py` и его Node-контракт.

После первого merge новый код становится доверенным в base; до этого его тестирует только read-only contract workflow. Событие `push main → workflow_dispatch` нужно дополнительно проверить на реальном открытом PR. Публичная биография по-прежнему должна содержать только факты и рассказ о человеке, без служебных редакционных заметок.
